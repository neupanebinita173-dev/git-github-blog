01 / Version control

Git — the time machine for your code

Git is a free, open-source distributed version control system. It records changes in files so you can see what changed, when it changed, and restore an earlier version when necessary.

Plain-English analogy
Imagine writing an assignment. You save versions such as assignment-final, assignment-final-2, and assignment-really-final. Git does this in a much smarter, organized way. It keeps a history of meaningful snapshots called commits.

The problem it solves

Without version control, it is easy to overwrite working code, lose earlier versions, or struggle to understand which change caused a bug.

Where it works

Git runs on your own computer. You can initialize a repository, save commits, create branches, and inspect history even when offline.

The basic Git journey

Working folderEdit files
→
Staging areaChoose changes
→
RepositoryCommit snapshot

Think of staging as preparing the exact changes you want included in your next saved snapshot.

Important Git commands

Terminal · Start a repository
git init
git status
git add .
git commit -m "First project version"
git log

What each command does: git init starts tracking a folder; git status shows what changed; git add . stages changes; git commit saves a snapshot; and git log displays commit history.

Branches: work safely in parallel

A branch is a separate line of development. You can build a new feature without changing the main version until you are ready to merge it.

mainStable project
↗
featureNew work
↘
mergeCombine changes
Terminal · Branch commands
git branch feature-home
git switch feature-home
# Make your changes, then:
git add .
git commit -m "Add homepage feature"
git switch main
git merge feature-home
Key takeaway: Git is your project's change-history manager. It helps you experiment without losing the work that already functions.
02 / Online collaboration

GitHub — your project's home on the internet

GitHub is an online platform for hosting Git repositories. It adds collaboration tools around Git, allowing developers to share code, review proposed changes, report bugs, and work together.

Plain-English analogy
If Git is the notebook where you record every version of your project, GitHub is the shared online bookshelf where you keep that notebook so teammates can access it.

Repository

An online project space containing files, folders, commits, and branches.

Pull request

A way to propose changes and ask others to review them before merging.

Issues

A place to report bugs, ask questions, and track work that needs doing.

Fork

Your own copy of another person's repository, which you can experiment with independently.

How your local Git project reaches GitHub

Your computerLocal repository
⇄
GitHubRemote repository
Terminal · Connect and upload
# Add your GitHub repository as a remote
git remote add origin https://github.com/USERNAME/REPOSITORY.git

# Set the main branch name
git branch -M main

# Upload your commits
git push -u origin main

Replace USERNAME and REPOSITORY with your own GitHub username and repository name. GitHub may ask you to authenticate before allowing the upload.

Useful GitHub features

FeatureWhat it is used for
README.mdExplains the project, setup, and usage.
Pull requestsReviews and merges proposed changes.
IssuesTracks bugs, ideas, and tasks.
ActionsAutomates workflows such as testing and deployment.
Key takeaway: GitHub makes Git projects easier to share, review, and build together. Git and GitHub are related, but they are not the same thing.
03 / Website publishing

GitHub Pages — take your website live

GitHub Pages is a static-site hosting service that publishes website files from a GitHub repository. It is useful for portfolios, project pages, documentation, and simple blogs.

Plain-English analogy
Think of your GitHub repository as the folder containing your website files. GitHub Pages is the display window that makes those files available as a website through a public web address.

What it supports

HTML for page structure, CSS for design, and JavaScript for browser-side interaction.

What it is not

It is not a general-purpose server for running a traditional backend such as PHP, Python, or a database.

Publish your first website

Create a repository

Create a new repository on GitHub. For a simple project, make it public if you are using GitHub Free.

Add your website files

Place an index.html file at the top level of the publishing folder. Add CSS and JavaScript files if needed.

Open repository Settings

Go to your repository, select Settings, then choose Pages from the sidebar.

Choose the publishing source

Under Build and deployment, choose Deploy from a branch, select main and /(root), then click Save.

Wait for deployment

GitHub builds and publishes the site. Check the Pages area or Actions tab for deployment status.

Open your live website

Your project site normally uses this address pattern: https://USERNAME.github.io/REPOSITORY/.

index.html · A tiny first website
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Website</title>
</head>
<body>
  <h1>Hello, GitHub Pages!</h1>
  <p>My first website is now online.</p>
</body>
</html>
Remember: GitHub Pages sites are publicly available on the internet. Never publish passwords, API keys, private information, or confidential files in your website repository.
Key takeaway: GitHub Pages turns a repository of static website files into a live website that people can visit.

Hands on

Build it yourself: a mini publishing lab

Let's create a tiny project and send it from your computer to GitHub. These commands assume Git is installed and you have created an empty GitHub repository.

1 · Create a project folder

Windows PowerShell
mkdir my-first-blog
cd my-first-blog

2 · Create an index.html file

Open this folder in VS Code and create index.html. Paste the small HTML example from the GitHub Pages section and save it.

3 · Start Git and save your first version

Terminal
git init
git add .
git commit -m "Create my first blog"

4 · Connect to your GitHub repository

Terminal · Replace the URL
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

5 · Publish with GitHub Pages

Open your repository on GitHub → Settings → Pages → Deploy from a branch → select main and /(root) → Save.

6 · Update your website later

Terminal · Save and publish another change
git add .
git commit -m "Update blog content"
git push

After the deployment finishes, refresh your website to see the latest version. You can check the Actions tab or Pages settings if you want to follow the deployment.

Pro tip: Make small commits with clear messages, such as Add homepage or Fix navigation menu. It makes your project history easier to understand.
Going deeper

When things go wrong

A calm checklist is better than panic. Here are common beginner problems and what to check first.

Git command not recognized

Git may not be installed, or Windows may not have refreshed its PATH. Install Git for Windows, reopen the terminal, and run git --version.

Push is rejected

The remote repository may contain commits you do not have locally. Run git pull and resolve any conflicts before pushing again.

GitHub Pages shows 404

Check that index.html is spelled exactly like that and is at the top level of the selected publishing folder.

Website looks outdated

Check the latest deployment in Actions, confirm your changes were pushed to the publishing branch, and refresh the browser.

Important distinction: GitHub Pages is designed for static websites. If your project needs server-side processing or a database, you will need an appropriate backend hosting service as well.
